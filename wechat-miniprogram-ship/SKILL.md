# 微信小程序：开发到上线

微信小程序这件事，**写代码不是难点，平台侧的不透明规则才是**。

官方文档讲 API 很全，但下面这些**查不到**，只有踩过才知道：

| 现象 | 真相 |
|---|---|
| 上传总失败，只报 `invalid ip: x.x.x.x` | 要把**这一个** IP 填进「代码上传密钥」的 IP 白名单 |
| 版本管理里上传者永远是「ci机器人1」 | `miniprogram-ci` 的 `robot` 只能是 1–30 数字，**官方明确不优化** |
| 云函数部署成功，但没法验证能不能跑 | 工具链只有"部署"，**没有"调用"** —— 得用模拟器 evaluate 绕 |
| 隐私指引填了却被驳 | 声明与代码不一致，**多了和少了都会被驳**，且修法相反 |
| 审核通过了却点不了发布 | 中间卡着 **ICP 备案**（备案不影响审核，只拦发布） |
| 「小程序 AI 开发模式」看着很美 | **未开放提审**，且原子接口环境**没有文件系统 API** |

## 端到端流程

| # | 阶段 | 验收判据（必须能自证） |
|---|---|---|
| 1 | 工程骨架 | 能编译；**名称/版本号有单一出处**，各处一致 |
| 2 | 本地自证 | 回归全绿；关键文件 hash 可复现；能区分"环境失败 vs 断言失败" |
| 3 | 云侧（可选） | 云函数 `Active` **且能被真实调用返回预期** |
| 4 | 平台配置 | 密钥/白名单/类目/**隐私指引**；隐私声明与 `wx.*` 调用一一对应 |
| 5 | 上传 | 成功；版本号与代码内常量一致；**上传者是本人**（用 IDE 通道） |
| 6 | 提审 | 版本描述/测试账号/隐私指引三项齐全 |
| 7 | 备案（**并行**） | 拿到备案号 |
| 8 | 发布 | 手动点发布（审核通过 ≠ 上线） |

## 三条最重要的结论

### 1. 上传有两条通道，**正式发版走 IDE 那条**

| | CI 通道（miniprogram-ci） | **IDE 通道（wechatide）** |
|---|---|---|
| 上传者显示 | **ci机器人N**（改不了） | **你的登录账号** ✅ |
| 需要工具开着 | 不需要 | 需要 |
| 用处 | 快速迭代、预览、headless | **正式发版** |

官方社区 2021-06-01 微信团队原话（针对"能否自定义 ci 机器人名字"）：
> 「反馈已收到，**我们并不打算优化**。」

**版本管理记录归属，比"命令方便"重要。**

### 2. 备案不影响审核，只拦发布

官方《小程序备案常见问答》：
> 问：小程序备案期间是否会对代码提审有影响？
> 答：……可以正常提交版本审核。

**→ 提审与备案并行做**，别串行等（管局环节最长 1–20 个工作日）。
官方错误码：未备案发布 → `86369 小程序上架需先完成备案`。

### 3. 隐私指引：**把 `wx.*` 调用全量列出来，逐条对照**

> 「如配置的用户隐私保护指引和代码实际里收集的用户信息**不匹配**以及未满足相应要求，
> 则**无法通过代码版本审核**」

**没调用的接口绝对不要声明。** 例：没用过 `getUserProfile`/`chooseAvatar`，
就一定不要声明「微信头像/昵称」——那是现成的驳回理由。

## 必须掌握的手法

### 真实调用云函数（因为工具链没有 invoke）
在模拟器里执行 `wx.cloud.init` + `wx.cloud.callFunction`：
```
官方工具 automation_evaluate --fn-source 'function(){ wx.cloud.init({env:"<env>"});
  return new Promise(res => wx.cloud.callFunction({name:"<fn>", data:{...},
  success: r => res(r.result), fail: e => res({err:e.errMsg})})) }'
```
调用方 openid = 模拟器 openid → **正好能验证管理员白名单这类鉴权**（通过 + 拒绝两条路径都测）。

### 查"IP 白名单该填哪个 IP"
**反直觉**：若本机走代理，普通探针查到的出口 IP **不是**微信看到的 IP。
- 探针看到的是**代理出口**（稳定，但微信不认）
- 微信看到的是**真实客户端 IP**（动态，会变）

**做法**：跑一次真实 CI 调用，从 `invalid ip: x.x.x.x` 里取那个 IP。
**把 CI 指向本地代理不一定有效** —— 有些实现会把真实客户端 IP 透传上游。

### Windows 引号地狱（国内环境高频）
| 坑 | 修法 |
|---|---|
| shell 吃掉 JSON 里的双引号 | **参数走文件**，不走命令行 |
| 文件带 UTF-8 BOM → `JSON.parse` 失败 | 读取后 `.replace(/^\uFEFF/, '')` |
| JSON 后有尾随内容 | **括号配对**截取，别 `slice(indexOf('{'))` |
| 返回嵌套层级随版本变 | **深度搜索**目标字段，别写死路径 |
| 带空格的路径传给 `cmd /c` | `shell:true` + 逐参数加引号 |
| `tasklist` 过滤中文进程名误报 0 | 改用 PowerShell `Get-Process` |

## 绝对不要做

| 不要 | 为什么 |
|---|---|
| 「审核员看到 A、用户看到 B」 | 运营规范 5.19.2 禁止人群对抗 |
| 声明未调用的隐私接口 | 声明与代码不匹配 → 直接驳回 |
| 想把 CI 上传者改成个人名 | 做不到；该改用 IDE 通道 |
| 用体积没变证明代码没变 | 同长度内容替换体积不变 |
| 等备案下来才提审 | 白等 1–20 工作日；可并行 |
| 审核通过就以为上线了 | 还要手动点发布 + 备案 |
| 在生成脚本之外手改生成物 | 下次跑生成器就回退 |

## 工具能力边界

| 工具 | 能做 | **不能**做 |
|---|---|---|
| `miniprogram-ci` | 上传、预览、**部署云函数** | 提交审核、设云函数环境变量、调用云函数 |
| 官方 CLI | 上传、预览、云函数增删改查、自动化 | 提交审核、调用云函数 |
| 官方 IDE 工具面 | 模拟器、截图、数据库读写、云函数部署 | 调用云函数、提交审核 |
| 官方 `agent` 命令 | AI 模式调试 | 需已开通；且未开放提审 |

**结论：「提审」没有任何自动化能力，必须人工在后台点。** 其余大部分可脚本化。

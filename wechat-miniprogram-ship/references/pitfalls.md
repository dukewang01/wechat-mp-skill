# 踩坑总表（按阶段）

> 全部来自真实项目实践。**每一条都标注了"为什么"和"怎么修"**。
> 官方结论标注出处，用前请核对最新文档。

---

## 阶段 1 · 工程骨架

### 1.1 名称/版本号有多个出处 → 一定会忘记改

**现象**：小程序名称同时出现在 `app.json` 的 `navigationBarTitleText`、
每个页面的 json、以及某个生成脚本的常量里。改一处忘一处。

**后果**：后台名称与小程序内显示不一致 → 撞官方 1.2.1(2)「名称与实际功能一致」。

**修法**：
- 定一个**单一出处**（生成脚本里的常量），其余由它生成
- 测试里**断言所有出现处一致**
- ⚠️ **如果名称同时要手改源码和生成器，两份都要改**（生成器那份通常在跑生成时覆盖源码）

### 1.2 生成器会覆盖手改

**现象**：跑了生成脚本后，之前手动打的补丁被回退。

**修法**：
- 生成流程 = **跑生成器 → 重放补丁**
- 用 **sha256 校验**关键文件确实变成了预期值，不要靠"看起来对"

### 1.3 体积监控的盲区

**现象**：改名后 CI 报的体积**一字节未变**。

**真相**：两个名字的 UTF-8 字节数恰好相同（如两个 3 字节汉字互换）。

**结论**：
- 体积监控只能发现「**字节量变化**」，发现不了「**同长度内容替换**」
- **不要用"体积没变"当作"代码没变"的证据**
- 判断代码是否真变了：看**版本号**、看**关键文件 hash**

## 阶段 2 · 本地自证

### 2.1 自动化测试的间歇性假失败

**现象**：昨天全绿，今天同样的代码报「连接被关闭」「通道不可用」。

**真因（按概率排序）**：
1. IDE 窗口被关 → automator 随之死亡
2. **残留的第二个 IDE 实例抢占端口**（装了多个版本/通道时高发）
3. `reLaunch` 在长生命周期会话里变成 no-op

**修法**：
- 失败先怀疑**环境**，再怀疑代码
- 关窗 → 重开 → 强制编译 → 重启自动化服务
- 清掉多余实例（官方 CLI 的 `quit` 是正确手段）

### 2.2 后台任务的生命周期陷阱

**现象**：起了个后台自动化服务，下一个命令就发现它没了。

**真因**：某些 shell 的后台任务（如 PowerShell `Start-Job`）**绑定在该 shell 进程上**，
shell 退出任务即消失。

**修法**：用 harness 管理的后台任务，不要用一次性 shell 起长期服务。

## 阶段 3 · 云侧

### 3.1 部署成功 ≠ 能跑通

`Active` 只说明代码传上去了，**不证明逻辑对**。

**修法**：必须**真实调用一次**并断言返回值（方法见 [ci-and-cloud.md](ci-and-cloud.md)）。

### 3.2 云函数环境变量经常设不了

**现象**：本机工具链里**没有任何**"设置云函数环境变量"的能力。

**后果**：逻辑依赖环境变量（如管理员白名单）时，改一次名单就要重新部署整个函数。

**修法**：**代码内兜底**（如 `ADMIN_FALLBACK` 常量数组）+ 环境变量优先。
并在文档里写明"要改白名单请改代码并重新部署"。

### 3.3 写操作可能需要人工确认

**现象**：数据库写操作返回 `Waiting for user confirmation`。

**修法**：只读操作通常无人值守可跑；**写操作别假设能自动完成**，脚本要能识别这个状态并提示人工。

## 阶段 4 · 平台配置

### 4.1 小程序名称是受控字段

**现象**：后台改名要提交官方审核，**可能不通过**。

**连带影响**：
- 名称定不下来 → **备案也要跟着等**（备案信息含名称）
- 备案完成后**再改名要同步做变更备案**，否则可能被警告/封禁/强制注销备案

**修法**：**尽快把名称定死**，别在提审/备案期间反复改。

### 4.2 隐私指引声明与代码不符 → 必驳

**两种方向的错，修法相反**：

| 驳回措辞 | 含义 | 修法 |
|---|---|---|
| 收集了未声明的信息 | 代码采了、指引没写 | **改指引，加声明** |
| 声明了未收集的信息 | 指引写了、代码没采 | **改指引，删声明** |

**做法**：把项目里 `wx.*` 调用**全量列出来**（一条命令即可），逐条对照。
详见 [privacy-and-categories.md](privacy-and-categories.md)。

### 4.3 服务类目选错 → 被要求资质

**现象**：名字里带某行业词，就以为该选那个类目。

**反例**：名字含「菜单」→ 觉得该选「餐饮服务」。
但官方「餐饮服务」管的是**点餐平台/外卖平台/餐饮场所**，会要求餐饮经营资质 → 必驳。

**修法**：**按功能实质选，不按名字选**。
个人主体可选类目远少于企业主体，且很多子项**免资质**（先查清单）。

## 阶段 5 · 上传

### 5.1 `invalid ip` —— 最高频的失败

**现象**：
```
[error] 20003 Error: {"errCode":-10008,"errMsg":"invalid ip: x.x.x.x"}
```

**修法**：把 **x.x.x.x 这一个 IP** 加进
「公众平台 → 管理 → 开发管理 → 开发设置 → 小程序代码上传 → IP 白名单」。

⚠️ **不要用别处查到的 IP**（见 [ci-and-cloud.md](ci-and-cloud.md) 的"查白名单该填哪个 IP"）。

### 5.2 上传者名字改不了

`miniprogram-ci` 的 `robot` 只能是 1–30 的数字，默认 1。
**官方 2021-06-01 明确答复不优化。**

**修法**：正式发版改用 **IDE 通道**（无 `robot` 参数，走登录身份）。

### 5.3 体积口径不可跨通道比

**现象**：同一棵树，CI 报一个数、IDE 报另一个数，差十几 KB。

**真相**：两者**编译口径不同**，不是 bug。

**修法**：**只在同一通道内纵向比**。告警只与"上一次同通道"的值比。

## 阶段 6 · 提审

### 6.1 首次被打回可能是机制，不是故障

有账号体系时官方要求提供测试账号（常见拒绝情形 3.3.4）。
**有些版本的提审页直接给填写入口，有些要首次被打回后才开放入口。**

**修法**：被打回先看理由是不是"未提供测试账号"。若是，**不用改代码**，重提并填账号即可。

### 6.2 测试账号必须是真账号

**绝不要**做「审核员看到 A、用户看到 B」：
- 运营规范 5.19.2 禁止「人群对抗」
- 运营规范 5.19 禁止「对不同用户群体展示不同内容」

**做法**：测试账号走与真实用户**完全相同**的注册流程。

### 6.3 「订单中心 path」只在交易类才要

非交易类（无下单/支付/订单）**留空**。

### 6.4 版本描述别写超过功能的话

写「保证合规」「审核通过」这类，会被判 **与实际功能不符**。
**如实描述功能点即可**（页面本身也提示"只用于审核，不展示给用户"）。

## 阶段 7 · 备案

### 7.1 备案不影响审核，只拦发布

官方明文（见 [privacy-and-categories.md](privacy-and-categories.md) 引原文）。
**并行做，别串行等。**

### 7.2 工信部短信核验有 24 小时时限

超时 **自动驳回**，要重新提交。收到 12381 短信当天就核验。

### 7.3 服务内容要和已选类目一致

个人主体**不得选经营性质**的服务内容。

### 7.4 备案后改名称要变更备案

不及时变更 → 平台可「警告、封禁功能、强制注销备案」。

## 跨阶段 · Windows 国内环境

| 坑 | 现象 | 修法 |
|---|---|---|
| shell 吃双引号 | `{"a":1}` 变成 `{a:1}` | 参数走**文件** |
| UTF-8 BOM | `JSON.parse` 报"不是合法 JSON" | `.replace(/^\uFEFF/, '')` |
| JSON 尾随内容 | `Unexpected non-whitespace character after JSON` | **括号配对**截取 |
| 嵌套层级变 | 写死 `a.b.c` 取不到 | **深度搜索** |
| 空格路径给 `cmd /c` | `'C:\Program' is not recognized` | `shell:true` + 逐参加引号 |
| `tasklist` 中文进程名 | 误报 0 个进程 | 改用 PowerShell `Get-Process` |
| 直连被重置 | `WinError 10054` | 出站可能强制走代理，别假设直连可用 |

## 一条元教训

**这个领域里，"文档说支持"和"实际能用"经常不是一回事。**

官方《API 支持列表》里**没列**的 API，不代表一定没有；
列了「支持」的，也不代表在你的场景下能用。

**做法：对关键能力一律实测一遍**，把实测结果记下来。
本项目里有两个重要结论（云函数其实能被调用、AI 模式原子接口其实没有文件系统）
都是**实测推翻文档推断**得到的。

# 隐私保护指引 · 服务类目 · ICP 备案

> 三件事常被混在一起，但**约束完全不同**：
> - **隐私指引** → 影响**审核**
> - **服务类目** → 影响**审核**（选错会要求资质）
> - **ICP 备案** → **不影响审核，只拦发布**

---

## 一、用户隐私保护指引

### 1.1 核心规则：声明必须与代码一致

官方明文：

> 「如配置的用户隐私保护指引和代码实际里收集的用户信息**不匹配**以及未满足相应要求，
> 则**无法通过代码版本审核**」

**所以：多了会被驳，少了也会被驳。** 且两种方向的修法**完全相反**：

| 驳回措辞 | 含义 | 修法 |
|---|---|---|
| 收集了未声明的信息 | 代码采了、指引没写 | **加声明** |
| 声明了未收集的信息 | 指引写了、代码没采 | **删声明** |

### 1.2 ★ 正确做法：先把 `wx.*` 调用全量列出来

**一条命令拿到全部隐私相关调用**（Windows PowerShell）：

```powershell
$src = "<项目根目录>"
$all = @()
Get-ChildItem "$src\pages","$src\utils" -Recurse -File -Include *.js | ForEach-Object {
  $c = Get-Content $_.FullName -Raw -Encoding UTF8
  [regex]::Matches($c, 'wx\.([a-zA-Z]+)') | ForEach-Object { $all += $_.Groups[1].Value }
}
$all | Sort-Object -Unique
```

**然后把结果逐条对照**，只声明**真正调用过**的。

### 1.3 常见隐私接口 → 对应声明

| API | 会触发什么声明 |
|---|---|
| `wx.chooseMessageFile` | 你选中的文件 |
| `wx.chooseMedia` / `wx.chooseImage` | 你选中的照片或视频信息 |
| `wx.setClipboardData` | 剪切板（**仅写入**，不读取） |
| `wx.getClipboardData` | 剪切板（**读取**，性质完全不同） |
| `wx.getLocation` / `chooseLocation` | 地理位置 |
| `button open-type="getPhoneNumber"` | 手机号码 |
| `wx.getUserProfile` / `getUserInfo` | **微信昵称、头像** |
| `wx.chooseAvatar` | **微信头像** |
| `wx.startRecord` / `getRecorderManager` | 麦克风 |
| `wx.chooseAddress` | 地址 |

**⚠️ 最容易被"多声明"的两项**：微信昵称 / 头像。
**如果代码里没有 `getUserProfile` / `getUserInfo` / `chooseAvatar`，就绝对不要声明这两项。**

### 1.4 指引的标准结构（官方 11 节）

```
1. 开发者处理的信息        ← 核心，逐条写
2. 第三方插件信息          ← 没引用插件就写"无"
3. 第三方服务商信息        ← 非代开发就写"无"
4. 信息的使用规则
5. 信息对外提供
6. 用户权益（查阅/更正/删除/注销）
7. 开发者对信息的存储
8. 联系方式                ← 必须真实可达
9. 补充文档
10. 日期
11. 引导语
```

**注意**：微信会**根据小程序版本的隐私接口调用情况自动展示"必填项"**，
这些项**不能被跳过**。所以"声明与代码一致"的第一步是**先看平台自动列了哪些必填**。

### 1.5 填写时的实用建议

- **手机号**：如果只在本机校验、不上传，**要在指引里写清"仅保存在本机、不上传、不发短信"** ——
  既准确，也避免审核员误解
- **上云的数据**：逐项列明**具体是哪几项**（如"姓名或工号、岗位、版本号"），
  不要笼统写"部分信息"
- **联系方式**：填**真实可达**的邮箱/电话（官方会核）
- **日期**：填实际生效日期

### 1.6 自查清单

| # | 检查 |
|---|---|
| 1 | `wx.*` 调用已全量列出 |
| 2 | 每一项声明都能对应到一个真实调用 |
| 3 | **没有任何未调用的接口被声明**（尤其头像/昵称） |
| 4 | 上云的数据逐项列明，落库的确实就是这几项 |
| 5 | 只在本机的数据写明"不上传" |
| 6 | 指引里的小程序名称与**当前后台名称**一致 |
| 7 | 联系方式真实可达 |

⚠️ **第 6 项容易忘**：指引是早先写的，后来改了名，指引里还是旧名 → 声明与实际不符。

## 二、服务类目

### 2.1 核心规则

> 2.1.1 小程序服务类目所对应的页面中的核心内容必须与该类目一致。

**按功能实质选，不按名字选。**

### 2.2 ★ 反例：名字带行业词 ≠ 该选那个行业类目

**例**：名字含「菜单」→ 直觉该选「餐饮服务」。

**但**官方「餐饮服务」管的是「**餐饮服务场所 / 点餐平台 / 外卖平台**」，
选它会要求**餐饮经营资质** → 必驳。

**正确做法**：看清功能实质（如"读文档 + 比对 + 出报告"）→ 选「**工具**」类。

### 2.3 个人主体的可选范围远小于企业主体

**个人主体通常只有这几类**（以官方文档为准）：

```
物流（快递业与邮政）· 教育服务 · 交通服务 · 生活服务
餐饮服务 · 旅游服务 · 工具 · 商业服务 · 体育
```

**金融、医疗、政务民生、社交、电商平台、商家自营等，个人主体不开放。**

### 2.4 「工具」类通常免资质

「工具」大类下的子项（**具体以官方文档为准**）通常**全免资质**：

```
记账 · 日历 · 天气 · 办公 · 图片处理 · 计算器
报价/比价 · 信息查询 · 预约/报名 · 健康管理 · 备忘录
```

**选类目前先查官方清单**：
<https://developers.weixin.qq.com/miniprogram/product/material/>

### 2.5 操作要点

- **可以随时加类目**，但**上架后改类目要重新审核**
- 加类目**通常免费、免资质**（取决于子项）
- **建议只加 1–2 个**最贴切的
- ⚠️ 某些类目（如游戏）**一旦选择不可改**，别乱选

### 2.6 被驳「类目与实际功能不符」怎么申诉

**要点**：把功能**照实拆解**，说明每一项都不属于被质疑的类目。

```
本小程序为<功能实质，如：办公类文档自查工具>：
用户选择自己手机里的<文件类型>或粘贴文本，工具依据预设判据做关键字比对，
输出<输出内容>。
不提供<被质疑类目的核心服务>、不做交易、不展示公开内容、无用户生成内容。
全程在本机完成，文件不上传。符合<所选类目>定义。
```

## 三、ICP 备案

### 3.1 ★ 备案不影响审核，只拦发布

官方《小程序备案常见问答》第七节第 1 条：

> **问：小程序备案期间是否会对代码提审有影响？**
> **答：2024 年 3 月 31 日前未完成备案的存量小程序可以正常提交版本审核。**

官方《小程序备案操作指引》第五节（备案成功）：

> 管局审核通过后，将下发的小程序备案号，代表你的小程序已完成备案，
> **可以进入下一步版本发布等流程**。

官方《备案常见问答》第八节第 3 条（未备案强行发布的报错）：

> `"errcode":86369,"errmsg":"小程序上架需先完成备案"`

**→ 结论：提审与备案并行做，别串行等。**

```
今天：提审（不需要备案）
  ├─ 审核通过 → 停在「待发布」✓ 这样是可以的
  └─ 同时去备案
       └─ 备案通过 → 点发布 → 上线
```

### 3.2 流程

| 环节 | 时长 |
|---|---|
| 填信息 → 平台初审 | 1–2 个工作日 |
| 工信部短信核验 | **收到 12381 短信后 24 小时内**必须完成 |
| 通管局审核 | 1–20 个工作日 |
| 下发备案号 | 通过后短信通知 |

**⚠️ 24 小时超时未核验 → 自动驳回**，要重新提交。这是最容易踩的一条。

### 3.3 个人主体材料

**只要个人有效身份证件**。人脸核身在平台内完成（管理员本人扫码，白/浅色干净背景）。

### 3.4 注意事项

| # | 事项 |
|---|---|
| 1 | **服务内容必须与已选类目一致**；个人主体**不得选经营性质**（如"批发和零售业"） |
| 2 | **名称会被预筛**：个人主体不得含「公司/集团/商城/商贸」及新闻金融医疗等前置审批关键词 |
| 3 | 部分省份（上海、江苏等）若身份证地址与备案省份不一致，需**居住证/暂住证** |
| 4 | 保持电话畅通（平台/管局可能电话核实） |
| 5 | 提交管局前可撤回重提 |

### 3.5 ★ 备案后改名称要变更备案

> 任意一个小程序备案信息发生变化时，**包括小程序名称**，都需及时发起**变更备案**。
> 不及时变更 → 平台将「警告、封禁小程序功能、**强制注销小程序备案**」。

**→ 名称最好在备案前就定死。**

## 四、三件事的先后顺序（建议）

```
1. 名称定下来（要走官方审核，可能不通过）
   ↓
2. 服务类目选好（按功能实质）
   ↓
3. 隐私指引写完（与 wx.* 调用逐条一致）
   ↓
4. 提审  ──────────────┐
                       ├─ 并行
5. 备案（名称已定，可以办）┘
   ↓
6. 审核通过 + 备案通过 → 点发布
```

**关键：名称要最先定，因为它同时影响"提审"和"备案"两条线。**

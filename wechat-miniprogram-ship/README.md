# wechat-miniprogram-ship — 微信小程序开发到上线

微信小程序从**建工程**到**过审上线**的完整工作方法 + 平台侧踩坑手册 + 可直接运行的脚本。

## 何时用

- 要开发/发布/迭代一个微信小程序
- 排查上传失败（`invalid ip`）、审核被驳、上传者显示为 `ci机器人`、
  云函数部署后无法验证、隐私指引报不合规等问题

## 这个技能解决什么问题

官方文档讲 API 很全，但**真正卡人的是平台侧的不透明规则**。下面这些文档里查不到，只有踩过才知道：

| 现象 | 真相 |
|---|---|
| 上传总失败，只报 `invalid ip: x.x.x.x` | 要把**这一个** IP 填进代码上传密钥的 IP 白名单；而且它**不是**普通探针查到的那个 IP |
| 版本管理里上传者永远是「ci机器人1」 | `miniprogram-ci` 的 `robot` 只能是 1–30 数字，**官方明确不优化** |
| 云函数部署成功，但没法验证能不能跑 | 工具链只有"部署"，**没有"调用"** —— 得用模拟器绕 |
| 隐私指引填了却被驳 | 声明与代码不一致，**多了和少了都会被驳**，且修法**相反** |
| 审核通过了却点不了发布 | 中间卡着 **ICP 备案**（备案不影响审核，只拦发布） |
| 「小程序 AI 开发模式」看着很美 | **未开放提审**，且原子接口环境**没有文件系统 API** |

## 用法

把整个 `wechat-miniprogram-ship/` 目录放进你的 agent skills 路径即可。

**技能主体是纯 Markdown**（`SKILL.md` + `references/`），不依赖任何外部服务。
**`scripts/` 是可选的自动化脚本**，需要 Node.js ≥ 18。

### 跑脚本

```bash
cd wechat-miniprogram-ship/scripts
cp config.example.js config.js     # 填 AppID / 项目路径 / 密钥路径 / 云环境ID
npm i miniprogram-ci

node msci.js status                 # 体检
node msci.js upide 1.0.0 "首个版本"  # 上传（上传者=你的登录账号）★推荐
node msci.js upload 1.0.0 "迭代"     # 上传（CI 通道，headless）
node msci.js fn my-function         # 部署云函数
node msci.js call my-function --file args.json   # 真实调用云函数（验证用）
node msci.js whichip                # 查白名单该填哪个 IP
node msci.js release-check          # 发布前自检（对照最后上传，防"发布未审代码"）
```

## 三条最重要的结论

### 1. 正式发版走 IDE 通道，不要用 CI 通道

| | CI 通道 | IDE 通道 |
|---|---|---|
| 上传者显示 | `ci机器人N`（改不了） | **你的登录账号** ✅ |

官方社区 2021-06-01 微信团队原话（针对"能否自定义 ci 机器人名字"）：
> 「反馈已收到，**我们并不打算优化**。」

**版本管理记录归属，比"命令方便"重要。**

### 2. 备案不影响审核，只拦发布

官方明文，且未备案发布的错误码是 `86369`。**提审与备案并行做，别串行等。**

### 3. 隐私指引：把 `wx.*` 调用全量列出来，逐条对照

**没调用的接口绝对不要声明** —— 这是最常见的驳回原因之一。

## 依赖与前提

- 微信小程序（非小游戏、非公众号）
- Node.js ≥ 18（仅脚本需要）
- 微信开发者工具已安装并登录（IDE 通道与云函数调用必需）
- 云开发可选（不用云开发也能用提审/通道部分）

## 边界与免责

- **不保证审核通过** —— 审核有主观成分。
- **平台规则会变**。文中引用的官方结论均标注出处，用前请核对最新文档。
- 不含任何具体项目的 AppID、云环境 ID、密钥或个人信息；脚本全部参数化。
- `config.js` 与 `node_modules/` 已在 `.gitignore` 中，**不会提交**。
